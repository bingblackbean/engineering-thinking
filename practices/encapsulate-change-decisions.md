# Practice: Encapsulate Change Decisions

* **Identity:** encapsulate-change-decisions
* **Type:** Practice
* **Status:** Draft

---

## Action

Identify design decisions that are likely to change and structure module boundaries so that those decisions remain encapsulated behind stable interfaces.

---

## Foundations & Mapping

* **Realizes Principles:**
  * `information-hiding`: Applies the principle by organizing module boundaries around design decisions that should remain hidden.
  * `deep-modules`: Applies the principle by exposing simple interfaces while encapsulating substantial implementation complexity.
* **Supported By Mental Models:**
  * `reduce-cognitive-load`: Provides the explanatory rationale for limiting the amount of implementation detail that must be considered when working across module boundaries.

---

## Boundary

This Practice defines a repeatable approach to organizing module boundaries around volatile design decisions. It does not prescribe a specific programming paradigm, design pattern, programming language, tool, or implementation technique.
