# Practice: Interface Review

* **Identity:** interface-review
* **Type:** Practice
* **Status:** Draft

---

## Action

Evaluate proposed or existing module boundaries and interfaces by examining the relationship between interface complexity and the complexity they encapsulate.

---

## Foundations & Mapping

* **Realizes Principles:**
  * `deep-modules`: Evaluates whether a module provides substantial functionality through a simple interface.
  * `information-hiding`: Checks whether module boundaries conceal design decisions that should remain hidden from consumers.
* **Supported By Mental Models:**
  * `reduce-cognitive-load`: Provides explanatory support for how simple interfaces can reduce the amount of context consumers need to consider.

---

## Boundary

This Practice defines the engineering activity of systematically reviewing interface designs and module boundaries. It does not enforce specific API review tools, code review checklists, OpenAPI/Protobuf specifications, pull request templates, or language-specific interface semantics.
