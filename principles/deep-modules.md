# Principle: Deep Modules

* **Identity:** deep-modules
* **Type:** Principle
* **Status:** Draft

---

## Claim

Modules should provide powerful functionality through a simple interface.

---

## Evidence

* **Source:** `sources/ousterhout-2018.md`
  * **Location:** Chapter 4 (Modules Should Be Deep), p. 22
  * **Quote Boundary:** "The best modules are those that provide powerful functionality through a simple interface. I use the term deep to describe such modules."

---

## Boundary

This Principle characterizes module depth by the relationship between a module's interface and the functionality or implementation complexity it encapsulates. It does not prescribe specific API coding style, class file organization, or implementation techniques.
